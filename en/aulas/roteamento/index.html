Lesson 7 · 15 min

Light model for routine work, top model for the hard stuff

You don't call your most experienced business partner to copy a spreadsheet. Models work the same way: the light model is fast and uses less of your plan, and it handles routine work; the top model thinks more slowly and is for the big plan, the hard problem, and anything that could cost a lot. The routing rule spells this out once.

Start the lesson

In this lesson, you’ll

  1. 1Which model is light and which is top in your tools
  2. 2What goes to each one
  3. 3When to move up to the top model, and explain why
  4. 4Choose the model in chat and in the terminal

Goal: write the rule that decides which model handles each task and classify your tasks as light or top.

02 · Which model is which in your tools

Names change over time. Check your model list.

1. In chat

In ChatGPT, Claude, and Gemini, the model selector is at the top of the conversation or near the text box.

Each option’s description tells you which one is fast for everyday use and which one reasons more deeply or is the most capable: the first is your light model, the second your top model. In Claude, Sonnet is for everyday use, and Opus is the most capable.

In a Project, choose the model at the start of the conversation. To move up, open a new conversation in the same Project with the top model.

2. In Codex

In Codex, /model shows the list available on your plan. In the 11/04/2026 list: gpt-6-luna (fast and economical, for easier tasks), gpt-6.1-terra, gpt-6.1-sol (the general-purpose one), and gpt-6-astra (for the most demanding work).

In the command, the model goes after -m.

3. In Claude Code

In Claude Code, /model switches the session model, and --model selects one when you launch it: sonnet for routine work, opus for difficult tasks.

The aliases always point to the latest version in each family.

4. Why it matters

With a subscription, the top model usually uses more of your usage limit and takes longer to respond.

Routine work on the light model keeps your limit free for when you really need the top model.

03 · The rule to paste

In chat, add it to the Project instructions; in the terminal, add it to the end of AGENTS.md or CLAUDE.md.

Routing rule (paste into the instructions)
Model rule:
Use the LIGHT model for routine tasks:
- reading dashboards, spreadsheets, and messages; copying data from one place to another
- weekly reports, summaries, and tables
- email drafts and short replies
- small edits to text, a spreadsheet, or a page

Switch to the TOP model when:
- it's a large plan or a new system
- the light model has made the same mistake twice
- you need to DECIDE something involving money or a contract (pay, negotiate, accept terms), or prepare a proposal for a major client
(reading and adding up invoices or bills is routine: keep using the light model)

When a task calls for the top model, tell me in one line: "I suggest the top model because ..." and wait for me to switch models.
If you're unsure, start with the light model and let me know if you get stuck.
Drafts and the gate apply to both.
Request · classify my tasks
Use the model rule above. Here’s my task list (lesson 1).
Return one line per task, in this format:
N | task | light or top | reason in a few words
Terminal (optional) · the same request at two levels
# routine work on the light model
codex exec --skip-git-repo-check -m gpt-6-luna -s read-only -o relatorio.md "report: follow AGENTS.md"
claude -p --model sonnet "report: follow CLAUDE.md" > relatorio.md

# difficult work on the top model
codex exec --skip-git-repo-check -m gpt-6-astra -s read-only -o plano.md "build a plan for the new estimating process"
claude -p --model opus "build a plan for the new estimating process" > plano.md
Simulation: illustrative example
1 | Weekly website report | light | read and summarize
2 | New contacts and drafts | light | routine, with a gate
3 | Invoices and bills to pay | light | read and add; top if the PDF can’t be read
4 | New client checklist | light | fixed steps
5 | Design the new estimating process | top | new system
  • Top model for everything "just in case": routine work gets slow and your limit runs out by Wednesday.
  • Light model for the contract: false economy. Expensive decisions go to the top model, and to you.
  • Switching without telling you: without the "because…" line, you can’t tell whether the rule is working.

05 · Practice: the rule in your Project

One rule, five tasks, one test.

E1 · Paste the rule

5 min

Paste the routing rule into the instructions for your agents’ Projects (or at the end of AGENTS.md / CLAUDE.md).

Done when: when you ask "which model would you use for the weekly report?", the agent answers light and gives the reason.

E2 · Classify your tasks

10 min

Use the "classify my tasks" request with the list from lesson 1. Check it with the checker.

Done when: The checker responds OK, and every task that DECIDES something involving money or a contract is marked for the top model or "do not delegate"; reading and adding up invoices can stay with the light model.

E3 · Find your light and top models

5 min

Open the model selector in the tool you use (or /model in the terminal), read each option’s description, and write down the name of the light model (the fast one for everyday use) and the top model (the one that reasons more).

Done when: you have both names written down and ran the weekly report on the light model.

07 · The lesson in three sentences

Light model for routine workRead, summarize, copy, and draft: quickly, using less of your limit.
Top model for difficult tasksBig plan, two failures with the light model, decision involving money or a contract.
Move it up and say why"I suggest the top model because…": the agent suggests it, you switch models, then check whether the rule works.
